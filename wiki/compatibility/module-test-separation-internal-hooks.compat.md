# Module/Test Separation and Internal Hooks Compatibility

- Document Class: Compatibility Note
- Status: Active
- Date: 2026-08-25
- Category: Test API and source organization compatibility
- Scope: Records the M6-prep refactor that keeps production crates smaller and moves test-hook ergonomics behind `kafkaman-test`.
- Sources: crates/kafkaman-sqlx/src/lib.rs; crates/kafkaman-sqlx/src/migration_runner.rs; crates/kafkaman-core/src/lib.rs; crates/kafkaman-config/src/config.rs; crates/kafkaman-test/src/harness.rs; tests/durable-send/src/lib.rs
- Related: wiki/decisions/consumer-test-tooling.decision.md; wiki/compatibility/m3-durable-receive-review-fix-api.compat.md

## Summary

Source organization and test API cleanup before M6 observability work, plus one
correctness fix in the migration runner (see *Behavior Change* below).

Production crate roots declare a module graph and a named public surface, and
nothing else. Each module declares its own imports rather than inheriting the
root's: an earlier round used `use super::*` in 49 of 53 module files, which
compiled but left the flat crate-root namespace that `include!` had created
intact, so the module boundaries were nominal. Every `kafkaman_*::Item` path
still resolves as before — the root re-exports are now named rather than globs,
which also makes each crate's public surface readable in one screen.

Real `mod` declarations remain load-bearing rather than cosmetic: `rustfmt` only
walks module declarations, so the original `include!`-based split left 9,083 of
the repo's 15,386 Rust lines invisible to the `cargo fmt --all -- --check` gate
in CI.

Moving items into sibling modules broke seven `[`item`]` doc links that had
resolved while everything shared one crate-root namespace. Neither `fmt` nor
`clippy` has anything to say about those, so `just lint` and the CI lint job now
also run `cargo doc --workspace --all-features --no-deps` under
`RUSTDOCFLAGS=-D warnings` — the same lesson as the `rustfmt` hole, applied to
the gate that this refactor was able to break.

Files named after two or three concatenated concerns were split along those
seams. `config_tables_router.rs` (479 lines) became `resolved_config`, `tables`,
`router`, and `ingest_failure`; `error_identifier_message.rs` became `error`,
`identifier`, and `message`; `outbox_relay.rs` — which contained no relay, that
being in `kafkaman-worker` — became `outbox_claim`, `outbox_mark`, and
`outbox_purge`. `kafkaman-worker` and `kafkaman-test`, untouched by the earlier
round, received the same treatment.

Enum lists that the compiler cannot check are generated rather than written.
`ReceivedFailureKind` and `ReceivedIngestFailureKind` each carried a hand-written
`ALL: [Self; N]` with a hardcoded length; every other accessor on them is a
`match self`, which the compiler checks for exhaustiveness, but `ALL` is what
`from_discriminant` and `from_problem_type` search. A variant added and missed
there produced no diagnostic — only a stored row that no longer read back. Both
now come from `discriminant_enum!`, alongside the `sql_enum!` that already did
this for `OutboxStatus` and `ReceiveStatus`, sharing one `count_idents!` in
`kafkaman-core`'s private `enum_macros`. `ALL`'s type and length are unchanged.

Duplication the flat layout had hidden was removed rather than moved. Eight
changesets that differed only in a name and a statement list are generated by one
`descriptor_changeset!` macro, so the `checksum_material` format — which is what
stops an edited changeset re-running under an applied version — exists once.
Four `record_received_failure`/`..._in_tx` twins became two functions taking
`&mut PgConnection`, which both a pool and a transaction can produce. The
integration suite's three-line "start Postgres, connect a harness" prologue,
repeated 79 times, is now `start_harness()`.

Largest Rust file: 342 lines, down from 4,382 before the refactor began and 650
after the first round.

## Behavior Change

`migrate` previously took a session-scoped `pg_advisory_lock` on a pooled
connection and released it after the migration. A dropped future — a `select!`
loss, a deploy timeout, a cancelled task — skipped the unlock and returned the
connection to the pool still holding it, leaving the schema unmigratable with
nothing to report why. Both entry points now take a transaction-scoped
`pg_advisory_xact_lock`, which Postgres releases on the rollback that dropping a
`Transaction` queues. Lock *keys* are unchanged and both lock types share one
lock space, so a rolling deploy still serializes correctly against an old
binary.

`migrate` now holds two pooled connections for the duration (the lock, and the
one changesets run on), because per-changeset commits cannot share a transaction
with a lock that must outlive them. Pools must allow at least two connections,
and `migrate` checks that up front: a single-connection pool would otherwise
block on the second acquire until it timed out, reporting a pool timeout that
says nothing about the configuration that caused it. `migrate_dry_run` still
needs only one.

## API Impact

- Production crates no longer expose consumer-facing `test-hooks` features.
  Their implementation-only observer gates are now named `internal-hooks`.
- Test ergonomics live in `kafkaman-test`, matching the consumer-test-tooling
  decision that consumers depend on a dedicated dev crate instead of enabling
  testing features on production crates.
- `kafkaman-test` keeps the old test spelling for existing integration tests:
  `DispatchTestHooks`, `DispatchFailureHookContext`,
  `dispatch_once_with_hooks`, and, behind the `redpanda` feature,
  `RdkafkaConsumerTestExt::with_post_durable_write_hook`.
- The hidden production names are `DispatchHooks`, `DispatchFailureEvent`,
  `dispatch_once_with_observer`, `IngestCommitEvent`, and
  `RdkafkaConsumer::with_post_durable_write_observer`. These exist to support
  the test toolkit and are not the preferred consumer test surface.

## Other API Changes

- `Config::from_str` is now `Config::parse`, with `FromStr` implemented
  alongside it. The old inherent method looked like the trait method and was
  not one.
- `IdempotencyKey`'s `PartialEq<&str>` is removed. It ran a SHA-256 derivation
  on every comparison and returned `false` when the derivation failed, which is
  test ergonomics in a library API. Compare against a derived key instead:
  `durable_send_tests::idem_key("...")`.
- `ReceivedIngestFailureRow` now composes `ReceivedIngestFailure` plus
  `created_at` rather than restating its ten fields. Field reads are unchanged
  via `Deref`.
- `ReceivedIngestFailureKind::discriminant`/`from_discriminant` moved onto the
  enum in `kafkaman-core`, from the hand-written pair of `match` blocks in
  `kafkaman-sqlx` that sat one crate away from the variants they enumerated.
- `Harness::try_publisher` returns `Result` where `Harness::publisher` panics on
  a Redpanda harness.
- `kafkaman_sqlx::Error` gains `MigrationPoolTooSmall { max_connections }`. The
  enum is not `#[non_exhaustive]`, so an exhaustive `match` over it needs a new
  arm.
- `kafkaman_rdkafka::Error::TestHook` is renamed `Observer`, and its message
  reads `ingest observer failed`. Feature-gated behind `internal-hooks`, which
  only `kafkaman-test` enables. It was the last test vocabulary left in a
  production crate's public error surface, which is the thing the
  `test-hooks` → `internal-hooks` rename existed to remove.

## Regression Fixed Within This Branch

The module split rewrote Kafka header decoding into a single pass over the
record. That pass resolved duplicate keys with `entry().or_insert()` for both
namespaces — correct for reserved headers, where the pre-split `header_value`
returned the first match, but a silent change for user headers, where the
pre-split `user_headers` used `BTreeMap::insert` and therefore kept the *last*
duplicate. A producer sending the same header key twice would have had a
different value persisted in the received row's `headers` column than on `main`.

User headers are back to last-wins, reserved stay first-wins, and both
directions are pinned by `duplicate_headers_resolve_in_opposite_directions_by_namespace`.
Verified the test fails against the regression before passing against the fix.

## Migration Guidance

Consumer tests that previously enabled `kafkaman-sqlx/test-hooks` or
`kafkaman-rdkafka/test-hooks` should depend on `kafkaman-test` as a
dev-dependency and import the hook helpers from that crate.

No database migration, config change, or behavior change is required.
